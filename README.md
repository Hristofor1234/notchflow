# NotchFlow

Островок у выреза экрана MacBook, который переключает режимы «Работа» и «Досуг»:
закрывает приложения прошлого режима, переключает рабочий стол (Control+1…9),
запускает приложения нового режима и показывает анимацию перехода на Metal.

Требования: macOS 26+, Apple Silicon, Command Line Tools (Xcode не нужен).

## Сборка и установка

```bash
./scripts/install.sh
```

Собирает приложение, прогоняет самопроверку настроек, ставит новую версию в
`/Applications/NotchFlow.app` и запускает её. Прежний `.app` уходит в Корзину.

## Версии и откат

Каждая версия хранится в своей папке `releases/<версия>-<сборка>/`:

| Файл | Что это |
|---|---|
| `NotchFlow.zip` | Приложение |
| `source.tar.gz` | Исходники, из которых собрано (у версий начиная с 3.0-202611032018) |
| `prefs-<дата>.plist` | Снимок настроек в момент, когда эту версию сменили |
| `*.sha256` | Контрольные суммы |

`install.sh` кладёт туда новую версию сразу при установке, а уходящую — вместе со снимком
настроек, и отправляет обе на сервер backup (контейнер 102 на proxmox,
`/srv/backups/notchflow/releases/`). На сервере хранятся все версии, файлы никогда не
перезаписываются; локально — 5 последних. Если сервер недоступен, установка всё равно проходит,
а папку можно отправить позже: `./scripts/backup.sh releases/<версия>-<сборка>`.

```bash
./scripts/rollback.sh                                  # список версий
./scripts/rollback.sh 3.0-202611032012                 # поставить версию, настройки текущие
./scripts/rollback.sh 3.0-202611032012 --with-prefs    # и вернуть настройки той версии
```

Если версии нет локально, она скачивается с сервера; контрольные суммы проверяются, при
расхождении откат отменяется. Текущая версия перед откатом сохраняется так же, как при установке,
поэтому вернуться обратно можно тем же `rollback.sh`.

## Настройки при обновлении

Настройки хранятся в `UserDefaults` (`com.hristofor.notchflow`, ключ `NotchFlow.preferences.v1`)
и обновлением не затрагиваются. Чтобы так оставалось:

- имя ключа и идентификатор приложения не меняются; при смене формата повышается
  `Preferences.currentSchema` и добавляется перенос старых данных;
- каждое поле и каждое приложение читаются отдельно — непонятное значение теряется одно,
  а нечитаемые данные целиком сохраняются под ключом `….unreadable.<дата>`;
- `install.sh` перед установкой прогоняет `--selftest-prefs`, сохраняет снимок настроек
  (`releases/<версия>/prefs-<дата>.plist`, он же уходит на backup) и после запуска сверяет,
  что настройки не изменились.

Разрешение «Универсальный доступ» сохраняется между обновлениями только при постоянной
подписи: один раз выполните `./scripts/setup-signing.sh` (попросит пароль Mac).

`./scripts/build.sh` только собирает `.build/NotchFlow.app`, ничего не устанавливая.

## Структура

| Файл | Что делает |
|---|---|
| `IslandWindowController.swift` | Панель у выреза, раскрытие/сворачивание, скрытие в полноэкранном режиме |
| `IslandView.swift` | Интерфейс: островок, кнопки режимов, вкладки «Приложения», «Переход», «Общее» |
| `ModeEngine.swift` | Порядок переключения режима |
| `AppController.swift` | Закрытие/запуск приложений, выбор `.app` |
| `SpaceSwitcher.swift` | Переключение рабочих столов через Control+N |
| `TransitionOverlay.swift` | Полноэкранная анимация (Metal-шейдер в строке, компилируется при запуске) |
| `Models.swift` | Настройки и их хранение в UserDefaults |
| `DebugSnapshot.swift` | `--snapshot <папка>` и `--preview-test` для проверки без экрана |

## Разрешения

Для переключения рабочих столов нужно разрешение «Универсальный доступ», а в
«Клавиатура → Сочетания клавиш → Mission Control» должны быть включены пункты
«Переход на Рабочий стол N». Сборка подписана ad-hoc, поэтому после каждой
пересборки macOS может снова попросить это разрешение.
